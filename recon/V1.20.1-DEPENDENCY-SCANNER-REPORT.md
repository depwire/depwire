## Three-case fixture and scanner implementation

The fixture includes a direct patched simple-git finding, a depwire-cli aggregate via simple-git with `fixAvailable:false`, and a synthetic genuinely unpatched advisory (metadata explicitly has no patched release). All three remain separate findings in table, JSON and SARIF. Full rendered artifacts: [table](v1.20.1-evidence/fixture.txt), [JSON](v1.20.1-evidence/fixture.json), [SARIF](v1.20.1-evidence/fixture.sarif).

| Case | Rendered distinction |
|---|---|
| Direct | `Vulnerable dependency: simple-git`; advisory GHSA-hffm-xvc3-vprc and link; upstream patch 3.36.0 |
| Aggregate | `Dependency vulnerable via transitives: depwire-cli`; `depwire-cli → simple-git 3.35.2`; `No automatic fix available in this dependency tree.` plus upstream patch 3.36.0 |
| Unpatched | `No automatic fix available in this dependency tree.` plus `No upstream patch exists for unpatched-fixture … according to the advisory.` |

Both npm exit paths share one renderer. Recursive via traversal retains every npm package entry, guards cycles, preserves mixed direct/transitive causes, and labels unresolved references. Parent aggregate ranges are never presented as parent advisory ranges. Installed versions come from npm lockfile nodes. GHSA ID/link (or numeric npm advisory source) stays in each description, which all existing reporters preserve; SARIF remediation stays in rule help.

The scanner uses the public GitHub advisory endpoint for patch metadata, deduplicated within each scan and bounded by a five-second request timeout. Offline, rate-limited, malformed or absent metadata produces **upstream patch availability unknown**, never an invented no-patch assertion. No credentials are read or sent. Tests cover metadata failure, cycles, mixed chains, missing nodes, both npm exit paths and malformed/error payloads. The new optional metadata lookup can add up to approximately five seconds to dependency scanning.
